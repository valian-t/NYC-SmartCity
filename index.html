Step 1 — SparkSession Setup

Entry point to Spark · driver config · AQE · Spark UI · local[*] parallelism

Python (PySpark) Step 1 — SparkSession 
from pyspark.sql import SparkSession

spark = (SparkSession.builder
  .appName("SmartCityNYC")
  .master("local[*]")
  .config("spark.driver.memory", "4g")
  .config("spark.sql.adaptive.enabled", True)
  .config("spark.sql.adaptive.coalescePartitions.enabled", True)
  .getOrCreate())

# Prove it works
print(f"Spark {spark.version}")
print(f"Cores: {spark.sparkContext.defaultParallelism}")
print(f"UI: http://localhost:4040")

⚡ How a GroupBy Job Runs

🔎 Physical Plan (Q1 explain)

== Physical Plan ==
Sort [pickup_hour ASC], true
+- Exchange rangepartitioning(pickup_hour, 8)
   +- HashAggregate(keys=[pickup_hour])
      +- Exchange hashpartitioning(pickup_hour, 8) ← SHUFFLE
         +- HashAggregate(partial_count, partial_avg)
            +- Project [fare_amount, hour(tpep_pickup_datetime)]
               +- Filter (fare_amount > 0 AND distance BETWEEN 0 AND 100)
                  +- FileScan parquet [2 cols] ← predicate pushdown
FileScan partial_agg Exchange = shuffle HashAggregate

Step 7 — Performance Analysis

Pandas vs PySpark · Core scaling · Amdahl's Law · Smart City insights

📊 Pandas vs PySpark — Same Job at Different Sizes

⚠️ Pandas wins on small data — no Spark startup overhead
✅ Spark catches up at ~3M rows and scales beyond memory

⚙️ Core Scaling — Amdahl's Law

⚡ 4 cores → 2.7× (not 4×) — file I/O and task scheduling are fixed overheads
